async inject(fn: Callable[..., Any], args: tuple[Any, ...] = (), kwargs: Mapping[str, Any] | None = None, *, sync_to_thread: bool | None = None) → Any[source]¶

Resolve all dependencies of fn, inject them into fn, and return its return value.

args and kwargs are passed to fn. When a parameter is declared a dependency but still passed explicitly, the explicit form will take precedence.

This method should not be used from within a dependency provider, as it can result in deadlocks: When solved dynamically, a dependency can request itself, creating a cycle, which can only be checked exhaustively if all dependencies are declared upfront. A best-effort check is performed to prevent calling this method from within a dependency, but it should not be relied on.

Parameters:

  • fn¶ – A callable or an InjectionTarget

  • args¶ – Positional arguments for fn

  • kwargs¶ – Keyword arguments for fn

  • sync_to_thread¶ – Whether a synchronous fn runs in a worker thread

Raises:

  • MissingProviderError – If a required dependency has no provider.

  • DIResolutionError – If the call is found to come from inside a factory; a best effort check to avoid misuse.

A registry of DI providers.

A registry holds every provider needed to satisfy the keys it declares.

A registry is mutable until the first time a graph is solved from it, creating a DIContext or calling predecessors_of(), at which point it freezes, validating the graph and disallowing further registrations.

Parameters:

  • name¶ – Name of this registry. Only used for debugging purposes in error messages

  • providers¶ – Providers available in this registry

  • scopes¶ – Available scopes, in order, outermost first. Defaults to ("app", "request", "handler")

Raises:

DIRegistrationError – If the scopes or the providers are invalid.

__init__(fn: Callable[..., Any] | None, kind: Literal['named', 'type'] | ProviderKind | None = None, scope: str = 'handler', key: DependencyKey | None = None, sync_to_thread: bool | None = None, signature: ParsedSignature | None = None) → None[source]¶

DI provider. A factory to produce a value.

A factory callable may be:

  • an async callable

  • a sync callable: In this case, sync_to_thread must be passed explicitly, to define how it should be invoked. Blocking synchronous callables should pass sync_to_thread=True, so they can run in a thread pool without blocking the main event loop. See Sync vs. Async for more info. A class is treated as a non-blocking sync callable. It’s __init__ and __new__ methods should never block

  • an async generator, yielding exactly once. The yielded value is the factory value. the code after the yield will be invoked as a cleanup step when this provider’s DIContext closes. If the context is closing with an active exception, that exception will be thrown into the generator. Cleanups are guaranteed to run in reverse order they providers were invoked in. Every cleanup will be invoked, even if prior cleanups raised an exception. Exceptions during cleanup steps are re-raised once all cleanups have completed.

  • a sync generator, yielding exactly once, with the cleanup step of an async generator. The code up to the yield runs in a worker thread, the cleanup step in a thread of its own, both in one contextvars.Context: a context variable set before the yield is set after it, and set for whoever resolves the provider. A context variable set where the context closes is set for the cleanup step

A provider may declare no ‘fn’, which makes it a seed. Seeds are expected to be given values for their context explicitly when that context is created. The shorthand for this is Provider.seed()

Parameters:

  • fn¶ – The factory callable, or None to declare a seed, whose value is given to the context owning its scope when it is built

  • kind¶ – Whether this provider is keyed by name or by type

  • scope¶ – Name of the lifetime-scope where the produced value is stored

  • key¶ – The key to register under. If omitted it is inferred: from fn.__name__ for a named provider, and from the return annotation (or the class itself) for a type provider

  • sync_to_thread¶ – Whether a sync callable runs in a worker thread

  • signature¶ – The parsed signature of fn, used instead of reading it from fn. For a functools.partial(), it may be that of the callable it wraps

Raises:

DIRegistrationError – If fn is not a supported callable, key contradicts kind, a seed is declared without a key or with a signature, or sync_to_thread contradicts the callable’s form.

class litestar.di.ValueGraphDivergence[source]¶

Bases: object

__init__(key: DependencyKey, provider: Provider, first_registry: str, registry: str, bindings: Mapping[DependencyKey, tuple[Provider | None, Provider | None]]) → None¶
litestar.di.check_divergence(registries: Iterable[DIRegistry], *, scopes: Collection[str] | None = None, ignore: Iterable[DependencyKey | Provider] | None = None, raise_on_divergence: bool = False) → None[source]¶

Check for divergences in the predecessors of providers shared by registries.

Why does this matter? A provider registered in one or more registry that, through differing predecessors in each registry, will create unique values below the lifetimes of its scope.

@provide(scope="app", key="session")
async def create_session(engine: NamedDependency[Engine]) -> Session:
    with Session(bind=engine) as session:
        yield session

@provide(scope="app", key="engine")
async def engine_one() -> str:
    return create_engine(<some params>)

@provide(scope="app", key="engine")
async def engine_two() -> str:
    return create_engine(<some other params>)

alice = DIRegistry("alice", [create_session, engine_one])
bob = DIRegistry("bob", [create_session, engine_two])

app_ctx = DIContext(registry=DIRegistry(), scope="app")
alice_ctx = DIContext(alice, scope="request", parent=app_ctx)
bob_ctx = DIContext(alice, scope="request", parent=app_ctx)

await alice_ctx.solve("session")  # there is now an 'engine' and a 'session' in app_ctx
await bob_ctx.solve("session")  # a distinct 'engine' and a 'session' are created in app_ctx

In this example, both registries share the provider for the ‘session’ key, but have different providers for the ‘engine’ key. Since ‘session’ depends on ‘engine’, this is a divergence. When resolving ‘session’ through ‘alice_ctx’ , it must get a different ‘engine’ then when resolved through ‘bob_ctx’, which the context will solve by invoking ‘create_session’ again, even if a value for its key is already present in ‘app_ctx’.

Raises:

DivergenceError – If raise_on_divergence is set, at the first finding.
